# 两轮独立验收与可复现交付记录

版本：`v0.1.0-beta.2`（建议版本；以 GitHub 发布状态为准）

## 第一轮：Brooks 式工程纪律

**判定：PASS WITH ISSUES。** 可继续维护并发布设备专用 Beta；不适合标记为适配所有机型的稳定版本。

### 发现并已经修复

1. 原仓库曾混合 5GB 的私人设备分区镜像/备份、厂商 APK/固件、LSPosed 研究文件、测试截图与可维护源码。重构为独立的 allowlist 开源仓库，禁止将原版系统镜像、书籍、密钥和私有备份提交。
2. 原 README 仍描述旧静态 PNG 和每十分钟更新，与设备上现有的动态模块不符。完全重写用户安装、架构、Recovery 与许可文档。
3. 主 APK 编译通配符打包已放弃的电源按键 Bridge、闹钟探针和 DreamService；现在只编译动态日历 `MainActivity` 与 `BrushRingDrawable`，并在构建前清理旧 Java/Dex 中间文件。
4. 移除主界面无效的“熄屏后强制刷新”广播实验及没有实际使用的 DreamService 声明，避免误导。
5. 提供独立的 `install/enable/disable/status/uninstall` 脚本，检查硬件型号、Android API、Root 和关键运行环境；模块默认关闭，用户按需开启。
6. 提供不再分发任何厂商映像的本地 OTA 生成工具，复用用户**合法取得**的 boot、update-binary 和可信的全文件 OTA 签名证书。
7. 建立独立的 11 项标准库单测、构建脚本、脚本语法检查、CI、网页浏览器冒烟测试和移动端 UI 测试。
8. 恢复保护脚本与 LSPosed 模块独立，Recovery 只能写 /cache，不需要直接访问受 SELinux 保护的 /data/adb。

### 已验证的工程证据

- Android 日历 APK、LSPosed 模块从**独立开源目录**编译，v2/v3 APK 签名检查通过。
- `python3 -m unittest discover -s tests -v`：**11/11 PASS**。
- `sh -n` 检查安装、关闭和恢复脚本：PASS。
- `node --check web/app.js`：PASS。
- Chrome 网页实际交互：模板、日期、字号、鼠标拖动、PNG 758×1024、JSON 导出和开关操作：PASS。
- 用户已有设备端系统测试：同一 PID 的 `system_server` 上连续两次模拟短按，进入实时日历并返回原任务；每分钟刷新日志和 DU 模式激活：PASS。
- 原厂 Recovery OTA 整包验签、/cache 写入及读取、Magisk 早期禁用空模块的两段真实链路：PASS。

### 明确未消除的工程风险（不能被产品表现良好抵消）

- `PhoneWindowManager` 和 `ViewRootImpl.setRefreshMode(1)` 为具体 Android 8.1 厂商实现：其他设备/系统不适配。
- system_server 内挂接仍有潜在崩溃风险；虽然两段回退组件实测成功，**真实 bootloop 灾难恢复未故意演练**。
- 系统返回页面依赖 Android task id；被系统回收任务或快速重复输入可能需降级至最近任务。尚未完成充分压力测试。
- 真实续航、72 小时运行、长按关机及大量连续实体按键测试尚需人工完成。
- 签名/升级：GitHub release APK 使用构建用签名证书；自行构建需要妥善保管自己的签名密钥，证书变更会影响直接覆盖安装。

## 第二轮：Jobs 式用户体验审查（独立于工程测试）

**判定：PASS WITH ISSUES。** 核心操作路径非常短，首次安装还存在 Root/LSPosed 配置门槛。

### 发现并已修复

1. 网页操作层级明确，但与真正系统时钟不是同一个渲染器，曾易让首次用户误解静态 PNG 是动态锁屏。将状态显式改为“网页预览 · 不同步设备”，文档明确二者边界。
2. 去掉网页多处不带信息价值的英文栏目标签，保留“选择排版／内容模块／锁屏预览／排版属性”等直观中文主标题。
3. 手机端实际测试 375、690、768 宽视口，页面无横向溢出，模板与导出按钮可达。
4. 阅读器端实机截图审阅：当前时间为最大视觉层级；月历日期和农历有层次；今日为手绘圈；底部节气为辅助信息。**不额外添加冗余锁屏按钮**，实体电源键是主操作。
5. 安装流程按“先防护、安装 APK、LSPosed scope、重启、显式启用、实体按键验收”重新整理，避免设备随安装突然改变电源行为。

### 尚未消除的用户体验限制

- 阅读器原生界面的“点按任意空白处退出”未设显式说明；为保持锁屏简洁，先在文档说明。
- 所需 Root + Magisk + LSPosed 不是普通 Android 用户的一键安装；为保证安全，不自动启用 system-server 模块。
- 手机端 Chrome 浏览器仅验证模拟触控宽度，不代替各种实际手机/平板设备的真实手势或屏幕截图验收。
- 用户反馈当前方案很好，但**真实按书籍页码、长按关机、25% 阈值、续航**仍需用户逐项独立签收。

## 发布和版权约束

将两个**第一方** APK 和源码放在 GitHub Release。不得上传原厂 boot、recovery、system、vendor、NeatReader、多看 APK、测试密钥、真实用户备份和别人的书籍。Root 刷机包由用户自行提供合法镜像和签名材料生成，仓库仅发布工具与有明确机型校验的模板。

两轮有独立结论，并保留各自的未解决项目；**Beta 是供用户安装审核，不宣称已经完成全部长期可靠性测试**。
